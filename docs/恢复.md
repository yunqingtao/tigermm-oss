# 恢复指南 —— 换机器 / 重装 / 灾难恢复

> 这份文档解决一个问题：**机器没了，怎么把 Tiger.M.M 完整地拿回来。**
> 仓库是**私有**的：`github.com/yunqingtao/tigermm`（340+ 文件，单提交，每日自动更新）

---

## 一、三步跑起来（新机器）

```bat
:: ① 拉代码
git clone https://github.com/yunqingtao/tigermm.git
cd tigermm

:: ② 装依赖 + 生成配置（会从 keys_template.json 建出 keys.json 骨架）
python install.py

:: ③ 还原凭据（API Key / GitHub token / relay 凭据 / 加密主密钥）
python scripts/secrets_unpack.py
::  → 提示"凭据口令"时，输入你存在密码管理器里的那串
::  → 7 个文件一次性到位：keys.json · keys_github.json · relay_tokens.json
::    · keys_github 的机器名副本 · .crypto.key · data/users.enc

:: ④ 起引擎
python main.py          :: CLI
python web_server.py    :: 网页版 → http://localhost:8800
```

**口令丢了怎么办**：`secrets.enc` 用 scrypt(口令) 派生密钥，**没有后门**，口令丢了密文就解不开。
补救 = 重新填一遍各家 API Key（`python scripts/secrets_pack.py` 重新打包即可）。
所以：**口令必须存一份在仓库之外**（密码管理器 / 纸上）。

## 二、仓库里有什么 / 没有什么

**有**（`ls` 可自己核）：
```
core/ tools/ gateway/ api/ ui/ cli/ utils/ mcp/     引擎与工具 (36 个工具)
tmm_skills/ skills/                                 技能 (25 个)
scripts/verification/                               门禁套件 (28 门) —— 自检: python scripts/hermes_verify.py
scripts/make_dist_repo.py scripts/daily_push.py     分发生成 / 每日推送
scripts/secrets_pack.py scripts/secrets_unpack.py   凭据打包 / 还原
sandbox/ lottery/ training/ demos/ reports/         子系统与内容
tests/ docs/ config/ storage/ static/ mobile_web/   测试与文档
secrets.enc                                         ★ 凭据密文 (口令才能解)
分发说明.md · README.md · docs/恢复.md               上手入口
```

**没有**（设计如此，见 `docs/data_boundary.md`）：
```
data/           对话史/感知/状态 —— 运行时生成, 第一次跑会自然建
backups/        本地回滚点 (55MB, 含一个 33MB 整机备份) —— 不进 git (git 不适合装大二进制)
logs/ tmp/      运行产物
keys.json 等明文凭据、.crypto.key、口令文件 —— 只以 secrets.enc 密文形式入库
*.zip 大备份包
```
> `data/` `backups/` 这类**要自己另外备份**：网盘 / 移动盘 / 另一台机器。
> 仓库负责"代码 + 技能 + 配置 + 凭据"，不负责"大文件与运行数据"。

## 三、每日自动推送（让仓库保持"活"）

```bat
:: 手动推一次（镜像开发仓库 → 提交 → 推 GitHub）
python scripts/daily_push.py

:: 只看会变什么，不提交
python scripts/daily_push.py --dry-run

:: 只提交到本地，不推
python scripts/daily_push.py --no-push
```

已注册 **Windows 计划任务 `TMM_DailyPush`**（每天 23:30）：

```bat
schtasks /Query /TN TMM_DailyPush /V /FO LIST      :: 查状态
schtasks /Run   /TN TMM_DailyPush                  :: 立刻跑一次
schtasks /Change /TN TMM_DailyPush /DISABLE        :: 暂停
schtasks /Change /TN TMM_DailyPush /ENABLE         :: 恢复
schtasks /Delete /TN TMM_DailyPush /F              :: 删除
```

> 换机器后要重新注册（任务不会跟着代码走）：
> ```bat
> schtasks /Create /TN TMM_DailyPush /TR "python <项目根>\scripts\daily_push.py" /SC DAILY /ST 23:30 /F
> ```

推送凭据：取环境变量 `GH_TOKEN`，否则读 `keys_github.json`。
凭据**不进 `.git/config`、不进命令行 URL**（用 `http.extraheader` 临时传）。

## 四、安全约定（重要）

| 事项 | 现状 |
|------|------|
| 仓库可见性 | **私有**（private）。转公开前**必须先轮换凭据** |
| 为什么私有也要加密凭据 | GitHub 对**私有仓库同样跑 secret scanning**；且凭据进了 git 历史就永远在（删了也在），将来转公开/加协作者就是裸奔 |
| 四类需轮换的凭据 | ① 163 邮箱授权码 ② 腾讯云 SMS secret ③ CLI 登录口令 ④ relay token |
| 明文凭据 | 只在本地（`keys.json` 等），已被 `.gitignore` 覆盖，不进 git |
| 口令文件 | `<仓库外>/secrets-passphrase-勿提交.txt` —— **在仓库外**，请复制进密码管理器后删除 |

## 五、验证仓库是否健康

```bat
python scripts/verification/verify_distribution_ready.py   :: 分发就绪 (凭据/个人路径/依赖/边界)
python scripts/verification/verify_tool_registry.py       :: 工具注册 (无工具被静默拒绝)
python scripts/verification/verify_static_hygiene.py      :: 静态卫生 (undefined name / 假兜底)
python scripts/hermes_verify.py                            :: 全部门禁 (28 门, 约 23 分钟)
```

门禁必须**在产物上**跑才有意义 —— 所以 `daily_push.py` 镜像完可直接对分发包目录再跑一次分发门禁。
