# 个人标识黑名单 —— 模板 (随分发包出门, 里面**没有任何真实标识**)
#
# 用法
# ─────────────────────────────────────────────────────────────────────
# 真实的那份叫 `_personal_denylist.txt`, **只在你的开发仓里**, 由 make_dist_repo 的
# `_personal_denylist.txt` 排除规则挡在分发之外。这样:
#   · 门禁能扫你的真实标识 (开发仓)
#   · 分发包里不带任何标识 (门禁自己也不泄露 —— 否则门禁就是泄露源)
#
# 想加自己的标识: 把它填进 `_personal_denylist.txt` (不是本模板), 每行一条:
#   <字面量>              纯字面量匹配 (大小写不敏感)
#   re:<正则>             正则匹配
#   # 开头                注释
# 然后跑:  python scripts/verification/verify_no_personal_data.py
#
# 本模板只放**通用形态** (对任何机器都成立)。
#
# ★ 2026-09-22 修 (模板自伤): 本模板的 `Users` 形态原先只要求 1 个字符
#   (`[A-Za-z0-9_.-]`), 于是**代码里的通用占位路径**都会被它扫中
#   (实测: 包内自扫 5 条命中 —— `C:\Users\x` / `C:\Users\a` 这类占位, 不是谁的真名)。
#   模板必须与开发仓真名单**同形**: 用户名要求 ≥3 字符, 放过单字符占位。
re:[A-Za-z]:[\\/]+Users[\\/]+[A-Za-z0-9_][A-Za-z0-9_.-]{2,}
re:\b(gho_|ghp_|github_pat_)[A-Za-z0-9_]{20,}
re:SCT\d{6,}[A-Za-z0-9]*
re:AKID[A-Za-z0-9]{12,}
re:\bsk-[A-Za-z0-9]{24,}
re:-----BEGIN [A-Z ]*PRIVATE KEY-----
